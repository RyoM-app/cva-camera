# CVAカメラ 0.3.0

体の横に置いたスマホのカメラ（内カメラ・外カメラ）で、耳珠・C7・肩峰の色マーカーをブラウザ上で追跡し、CVAと渡邉角をリアルタイムに計算して記録します。
保存されるのは、時刻・マーカーの座標・角度・端末の傾きだけです。映像は「映像の保存」を選んだときだけ端末に保存し、どこにも送信しません。

角度の定義と計算は `cva-marker-tracker/cva_tracker.py`（Python版）と同じです。

公開ページ：https://ryom-app.github.io/cva-camera/

## 0.3.0の変更点

| 変更 | 内容 |
|---|---|
| 案内中・移行中のラベル | 音声の案内中は `label`＝「案内中」、案内のあと姿勢を変えている間（既定3秒）は「移行中」。目標の姿勢は `target_label` 列に入る |
| うなずきの自動検出 | 最初と最後のうなずきを検出してから次へ進む・終わる。検出できなければ、最初は8秒、最後は12秒待って先へ進む |
| センサーによる傾き補正 | 撮影の直前1秒間の重力センサーの平均から、カメラの傾きを自動で補正する。手動で水平線を2点タップする方法も残した |
| カメラの選択 | 内カメラ・外カメラを選べる（傾き補正の向きも自動で切り替わる） |
| 映像の保存（任意） | 「しない／計測結果を重ねた映像（発表用）／元の映像」から選ぶ |

## 使い方（1人で実験できます）

1. 公開ページを、側面カメラ用のスマホのSafari/Chromeで開く
2. スマホを体の真横に、**縦向きで立てて**置く（高さは肩、1〜2 m）。内カメラなら画面を自分に向ける
3. カメラを選んで「カメラを開始」→ カメラ（とiPhoneでは動きのセンサー）の使用を許可する
   - 映像の上の**水色の点線**が、センサーで求めた水平線です。壁や床の線と平行になっているか確かめてください
   - 下の「端末の傾き」が左右5°・前後10°を超えると色が変わります。できるだけまっすぐ立ててください
4. セルフタイマーを選んで「写真を撮る」。合図の音が鳴るまで、正面を向いて楽な姿勢でいる
5. 撮った**写真の上で**、耳珠 → C7 →（肩峰）の順にマーカーをタップする。写真でのCVAと、傾き補正の値が表示される
   - 水色の点線が明らかにずれているときだけ、「水平線（手動・任意）」で本当に水平な線の上を2点タップする
6. 1姿勢の時間・移行の時間・映像の保存・進め方を選んで「記録スタート」
   - **自動**：準備（2秒）→ うなずき → ［案内中 → 移行中 → 姿勢］×（基準・うつむく・顎を突き出す・目線だけ下げる・基準）→ うなずき → 終了
   - **手動**：姿勢を変えるたびにラベルを押し、最後に「記録停止」
7. 「CSVを保存」「全記録JSONを保存」（映像を選んだときは「映像を保存」も）

画面は左右反転していません（記録される座標と同じ向き）。

## 記録の中身

| 列 | 内容 |
|---|---|
| `epoch_ms` | Unix時刻[ms]。`performance.timeOrigin + perf_ms`。posture-labの `meta.timeOrigin + t` と同じ基準 |
| `capture_perf_ms` | 撮影時刻（ブラウザが対応している場合のみ） |
| `label` | 自動：準備・うなずき・案内中・移行中・各姿勢／手動：押したラベル |
| `target_label` | その区間で目標にしている姿勢（案内中・移行中にも入る） |
| `stage`, `step` | 区間の種類（`prep` `nod` `guide` `transition` `hold` `manual`）と姿勢の番号（0〜4） |
| `tragus_x` … `acromion_area` | 各マーカーの重心（映像の画素、左上が原点）と面積 |
| `cva_deg`, `watanabe_deg` | CVA、渡邉角（度）。傾き補正後 |
| `valid` | CVAが求まったか（1/0） |
| `device_roll_deg`, `device_pitch_deg` | 端末の左右・前後の傾き（重力センサー） |

**解析では `label` が姿勢名の行（`stage = hold`）だけを使い、案内中・移行中の行は除いてください。**

JSONには、色の設定・解像度・傾き補正（値、センサーか手動か、撮影時の重力）・映像の情報・イベント列が入ります。
イベント：`record_start`、`stage`（区間の切り替わり）、`sync_cue`（うなずきの合図）、`nod_detected`（基準のCVA、最小のCVA、深さ、最も深くなった時刻）、`nod_timeout`、`video_start`、`record_stop`。

### 傾き補正の考え方

端末の座標（x：画面の右、y：画面の上、z：画面の手前）で重力の反力を g とすると、端末の左右の傾きは θ = atan2(−gx, gy)（画面を見て時計回りが正）。
左右反転していない内カメラの画像では、本当の水平線が θ だけ傾いて写り、外カメラでは −θ 傾きます。この角度だけ座標を戻してから角度を計算します。
端末を縦に立てて置く前提です（横向き・逆さまには対応していません）。

### うなずきの検出

合図の直前1.5秒のCVAの中央値を基準にし、そこから6°以上下がって、3°以内に戻ったら「うなずき」とします。最も深くなった時刻（`min_epoch_ms`）が、posture-labとの時刻合わせの基準になります。

### 2台のスマホの時刻合わせ

両方の端末の時計（Unix時刻）で大まかに合います。端末の時計どうしは数十〜数百ms ずれることがあるため、最終的には**うなずきの山**で合わせます。

### 映像の保存

- 計測結果を重ねた映像：マーカーの円、CVAの扇形、角度・ラベル・経過時間を重ねた映像（長辺1280画素まで、30 fps）。ゼミの発表用
- 元の映像：カメラの映像そのもの
- 形式はブラウザによって MP4 か WebM になります。Macのプレゼンで再生できないときは、変換が必要な場合があります
- 顔が写るので、被験者の映像は公開の場所に置かないでください。本実験では「しない」を選んでください

## 動作確認（パソコンのブラウザの疑似カメラ・疑似センサー）

| 試験 | 結果 |
|---|---|
| 疑似カメラ：既知のCVA 55°→40°の映像（0.2.0） | 275/275フレームで検出。最大誤差 0.22° |
| 疑似カメラ：実際のマーカー写真（0.2.0） | CVA 42.74°（Python版 42.64°） |
| 0.3.0：カメラが6°傾いた映像（CVA 50°）＋疑似の重力センサー（内カメラ） | 補正 6.0°、写真でのCVA 50.2°、記録の平均 50.01° |
| 0.3.0：同じ映像で外カメラを選び、端末の傾き −6° | 補正 6.0°、写真でのCVA 50.2°（向きの切り替えが正しい） |
| 0.3.0：4秒ごとに14°のうなずきが入る映像 | 最初・最後とも検出（深さ 13.8°）、ラベルが順に記録された |
| 0.3.0：うなずきのない映像 | 最初8秒・最後12秒待って先へ進み、`nod_timeout` が記録された |
| 0.3.0：計測結果を重ねた映像の保存 | 30秒で約0.4 MB（合成映像のため小さい） |

実機での確認：0.2.0をAndroidで実行（2026-10-23）。0.3.0の実機での動作、特に**重力センサーの向きと映像の保存は、まだ確認していません**。最初の撮影で、水色の点線が壁の線と平行になるか確かめてください。

## 調整

「検出の調整」で、色相の許容幅、最小の大きさ、処理の解像度を変えられます。「色の検出範囲を表示」で、色として拾っている範囲を紫で確認できます。
